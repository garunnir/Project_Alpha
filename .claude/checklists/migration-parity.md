# Migration Parity Checklist

**목적:** 경로/스택 교체·하이브리드 후 패리티 빈칸을 증상별 재현으로 메우지 않는다 (`bug-fix-gate.mdc` · 본 체크리스트).

**관련 룰:** `.cursor/rules/migration-parity.mdc` (always) · 완료 선언: `.cursor/rules/agent-completion-gate.mdc` · `.claude/checklists/agent-completion-gate.md`

**완료 조건:** 아래 계약을 **기본 경로로 켜기 전에** 통과. 도메인 세부 항목은 해당 UI/시스템 문서에만 두고, 여기엔 넣지 않는다.

**기능 불변 최적화·내부 교체**도 동일 게이트. §C 체크리스트를 작업 계획/PR에 두고 전항 통과 후 완료 선언.

---

## A. 공통 (모든 이주)

- [ ] 변경 전 동작을 계약 목록으로 적어 두었다 (작업 메모 → 머지 전 도메인 문서에 반영)
- [ ] “새 조각만 되면 완료”가 아니라, 구경로가 주던 **주변 계약**을 빈칸으로 인정했다
- [ ] 두 시스템 공존 시 경계 SSOT를 적었다 (입력 / 좌표·단위 / 그리기·레이어·수명)
- [ ] 패리티 미완이면 구경로·Revert·flag off — **기본 경로로 켜지 않음** (명시 승인 없으면)
- [ ] 예상 공백·회귀를 `bug-fix-gate.mdc` §MUST NOT 방식으로 메우지 않았다
- [ ] 사용자 재현 요청은 **계약 밖 신규 버그** 또는 **검증 후에도 남은 회귀**에만

## B. 기본 경로로 켜기 직전

- [ ] 계약 항목을 에이전트/개발자가 한 바퀴 검증했다
- [ ] 관련 도메인 문서에 한계·Revert·이 체크리스트 링크를 갱신했다
- [ ] Pending이 남아 있으면 기본 경로로 켰다고 선언하지 않았거나 승인을 받았다

## C. 기능 불변 최적화·내부 교체 (가상화·풀링·캐시·렌더 경로 등)

**When:** 사용자-facing API·UX를 바꾸지 않는다고 명시한 리팩터/성능 작업.

**경량 예외 (§C 전체 생략 가능):** ≤2파일, net ≤40줄, 공개 API·직렬화·런타임 경로 불변, 도메인 스모크 1회로 충분한 수정 (`CLAUDE.md` post-task skip과 동일 기준).

### C1. 작업 전 — 기능 인벤토리

- [ ] **기능 목록**: 교체 대상이 제공하던 동작을 항목으로 적었다 (입력·선택·DnD·스크롤·이벤트·동기화 경로 등)
- [ ] **소비자**: 누가 호출/구독하는지 1-hop 이상 적었다 (직접 참조·이벤트·Inspector 배선)
- [ ] **엣지케이스**: 빈 상태·드래그/스크롤 중·양쪽 창·리사이즈·대량 데이터 등 **깨지기 쉬운** 시나리오를 적었다
- [ ] **성공 기준**: 측정 가능한 수용 기준을 적었다 (예: 활성 GO 상한, 프레임당 layout rebuild 금지)

긴 매트릭스는 작업 계획·PR 본문에 두고, 도메인 문서에는 요약 + 링크만 남긴다.

### C2. 기본 경로로 켜기 전 — 검증 게이트

- [ ] C1 기능 항목 **전항** Play 또는 동등 수동 검증 (하나 실패 = 미완)
- [ ] C1 엣지케이스 **스팟 체크** 완료 (전부가 아니라도 “깨지기 쉬운” 항목은 필수)
- [ ] 성능/회귀: C1 성공 기준 충족 또는 미충족 사유·Pending 명시
- [ ] §A·§B 공통 항목 충족 (기본 경로·문서·Pending)

**MUST NOT:** “내부만 바꿨다”로 체크리스트 없이 기본 경로로 켬 · `bug-fix-gate.mdc` §MUST NOT.
